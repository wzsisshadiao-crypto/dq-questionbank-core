# Importers

Importers translate source documents into a `QuestionSet`.

## Built-in importers

- JSON accepts a question set, question array, or single canonical question.
- Markdown fully restores files generated by the built-in exporter. Its
  best-effort choice parser also accepts Markdown list items with zero to three
  leading spaces; four-space code blocks are not treated as canonical choices.
  Literal `### Choices`, `### Solution`, and `### Hint N` lines inside content
  are backslash-escaped on export and restored as content on import. The same
  reversible escape protects literal lines shaped like the `**Answer:**`
  marker.
- LaTeX fully restores generated files and provides a basic `enumerate`
  fallback. Only items in an outer `enumerate` become questions; nested
  environments remain source text inside their outer question.
- DOCX reads the visible convention produced by the built-in exporter and extracts inline images.

## DOCX example: documented field labels

The DOCX importer uses a small documented paragraph convention for question
fields. For example:

```text
Question q1
Type: short_answer | Language: en
Question: What is 2 + 2?
Answer: text:4
```

**Preserved:** The question ID, type, language, stem, and answer are
recognised when these documented labels are used.

For choice answers, both the exporter's single-quoted list and a JSON-style
double-quoted list are accepted. For example, `Answer: choices:["A", "B"]`
imports the canonical choice IDs `A` and `B`; the quote characters are not
part of the IDs.

**Best effort:** Surrounding Word formatting is not part of the canonical
import contract. The importer primarily relies on paragraph content and the
documented field labels.

**Intentionally unsupported:** Arbitrary Word layouts that visually represent
these fields without using the documented labels are not guaranteed to
import correctly. In particular, `Question <id>` must use a Word Heading
style — plain body text reading "Question q1" will not be recognized as a
question boundary.

## Trust boundary

Treat every input as untrusted. Importers must not execute macros, shell commands, embedded scripts, or instructions found inside content. They must not fetch remote assets implicitly. Extracted filenames must be generated by the importer rather than trusted from the document.

## Adding an importer

Implement `QuestionImporter`, keep parsing separate from storage, document supported constructs, and add synthetic fixtures for malformed input, Unicode, math, images, and composite questions.
